# 🎓 RateMyProf — Politecnico di Torino

**A student-built professor directory and rating platform for PoliTo.**
Scrape every department, browse 5,400+ staff records, and rate teaching staff across five dimensions — with Google sign-in, Supabase persistence, and a moderation workflow baked in.

## ✨ What's inside

| Layer | What it does |
|---|---|
| **🕷️ Scrapers** | Two Python scrapers: a tuned one for all 11 PoliTo departments, and a generic one that crawls *any* university site with heuristics and optional Playwright fallback. |
| **📊 Datasets** | Clean JSON/CSV exports of every person on PoliTo's department directories, with role categorisation, teaching-staff flags, stable canonical IDs, and per-category splits. |
| **💻 Frontend** | A fast React + Vite + Tailwind single-page app: search, filter by department / role, star ratings, review text, CSV export. |
| **🔐 Backend** | Supabase Postgres schema with row-level security, Google OAuth, one-rating-per-user-per-professor upserts, and a full moderation lifecycle. |

## 🚀 Quick start

### 1 · Run the frontend

```bash
cd frontend
npm install
cp .env.example .env        # fill in your Supabase URL + anon key
npm run dev                 # → http://localhost:5173
```

Without Supabase credentials the app falls back to `public/professors.json` in read-only mode. That file is not in the repo — generate it with the scraper (step 3) and copy `professors.json` into `frontend/public/`.

### 2 · Set up Supabase (for ratings & login)

1. Create a project at [supabase.com](https://supabase.com).
2. Paste **`frontend/supabase_ratings_schema.sql`** into the SQL editor and run it.
3. Enable the **Google** provider under *Authentication → Providers*.
4. Add `http://localhost:5173` (and your production URL) to *Redirect URLs*.
5. Drop the project URL and publishable key into `frontend/.env`.

The full walkthrough, moderator role assignment, and troubleshooting live in [`frontend/README.md`](frontend/README.md).

### 3 · Re-scrape the data (optional)

```bash
pip install requests beautifulsoup4

# All 11 PoliTo departments, polite 2–4 s delay between requests
python polito_scraper.py --output-dir data

# Teaching staff only, custom pacing
python polito_scraper.py --only-teaching-staff --min-delay 1 --max-delay 2
```

Point the generic scraper at any university:

```bash
pip install playwright && playwright install   # optional, for JS-heavy sites
python university_professor_scraper.py --university-url https://www.example.edu --fetch-mode auto
```

## 🔐 How ratings & moderation work

```
 student ──Google OAuth──▶ Supabase Auth
    │
    ▼  upsert (user_id, profile_url)
 professor_ratings ──trigger──▶ overall_rating recomputed server-side
    │                             moderation_status = 'pending'
    ▼
 moderator (JWT app_metadata.role = 'moderator')
    approves / rejects / flags / hides
    │
    ▼
 professor_rating_summary view ──▶ public UI (approved + visible only)
```

- **One rating per user per professor** — enforced by a unique constraint and used as the upsert key.
- **Row-level security** — anonymous users see only approved ratings; users can edit only their own; moderators see and manage everything.
- **Tamper-proof moderation fields** — a trigger blocks non-moderators from touching `moderation_status`, `is_hidden`, `report_count`, etc.
- **Server-side truth** — the overall score is always recomputed in Postgres, never trusted from the client.

## ⚠️ A note on data & ethics

The scrapers read **publicly listed** PoliTo department directories for an educational student project. To respect staff privacy, **no scraped records are committed to this repository** — every output file is git-ignored, and the sample data in the UI uses placeholder names. The scrapers are polite by default (randomised delays, identifiable user agent). If you run them, keep it that way.
